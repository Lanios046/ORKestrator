# ORKestrator

Настраиваемый оркестр локальных моделей: C++23, Qt 6 и [QtNodes](https://github.com/paceholder/nodeeditor).
Python не используется ни в интерфейсе, ни в исполнителе.

## Граф агентов

В приложении существует один тип узла — **агент**. Назначение определяется его инструкциями.
Встроенных сущностей PM, критик, разработчик и фиксированной последовательности этапов больше нет.

У каждого агента:

- собственная модель LM Studio и отдельный контекст;
- системные правила и поручение при каждом входе;
- два выхода: положительный и отрицательный результат;
- разрешенные инструменты файлов и команд;
- режим мышления, лимит ответа, таймауты и бюджет инструментов;
- сохранение контекста либо сброс при каждом посещении;
- автоматический переход по результату либо ручное продолжение.

Соедините нужный выход со входом следующего агента. Один выход ведет к одному агенту; вход может принимать связи от нескольких агентов.
Допустимы циклы между узлами, например отрицательный результат возвращает к предыдущему агенту для доработки.
Изменение графа или его загрузка сами по себе не запускают модели.

Положительный и отрицательный результаты не означают фиксированный вердикт ревью: их смысл задают правила агента.
По умолчанию поле результата называется `result`, значения — `positive` и `negative`.
Имена поля и значений можно менять в свойствах, например на `verdict`, `approved` и `revise`.
Упоминание проверки в инструкциях не создает отдельного типа узла.

## Начало работы

1. Укажите адрес LM Studio (по умолчанию http://127.0.0.1:51325), при необходимости API-ключ и папку рабочего проекта.
2. Обновите модели и выберите модель в свойствах агента. Кнопка назначения модели заполняет пустые узлы.
3. Добавляйте агентов и соединяйте выходы с входами мышью. Настройте инструкции, инструменты и критерии положительного/отрицательного результата.
4. Выделите стартового агента и нажмите «Стартовый агент».
5. Примените настройки, введите задачу и нажмите «Новая задача».
6. Если включен автопереход, ответ с соответствующим значением передается подключенному агенту. Неподключенный выход завершает ветку.
7. Для ручного управления отключите автопереход у нужного агента. Можно выбрать ветку вручную, повторить агента с уточнением или завершить работу.

Ответы пользователя на вопросы агента передаются через поле уточнения и повтор текущего агента.
Никаких обязательных опросников и отдельных протоколов для разных ролей нет.
Лимит автопереходов защищает циклический граф от бесконечного исполнения. При его исчерпании контексты сохраняются и можно продолжить вручную.
Число агентов не привязано к прежним семи ролям.

## Контексты и результаты

При переходе агент получает исходную задачу, входной результат и уточнение пользователя.
История другого агента целиком не копируется. При повторном входе собственная история сохраняется, если не включен ее сброс.
Системные правила обновляются из свойств узла; сброс выбранного контекста доступен отдельной кнопкой.

Пайплайн сохраняется в JSON: агенты, инструкции, параметры, координаты, связи и стартовый узел.
Сессия содержит граф, задачу, рабочую папку, контексты, результаты посещений, результаты инструментов и журнал.
API-ключ не сохраняется; его можно задать в окне или через LM_STUDIO_API_KEY.
Автосохранение сессий находится в graph-sessions в пользовательском каталоге данных ORKestrator.
Редактор восстанавливает последний граф при следующем запуске.
Загрузка сессии не запускает модели автоматически: продолжение выбирает пользователь.

Старые сессии фиксированного семиролевого исполнителя имеют другой формат и новым исполнителем не загружаются.

## Инструменты

Для каждого агента отдельно разрешаются list_files, read_file, find_files, search_text, write_file и run_command.
Права пустого нового агента по умолчанию не включают инструменты. Разрешенные операции выполняются внутри агента автоматически.
Перед перезаписью существующего файла агент должен сам прочитать актуальное содержимое; чтение другим агентом этого не заменяет.
Пути файловых инструментов ограничены рабочей папкой. Выход через .., доступ к .git и ссылки наружу запрещены.
Запись выполняется через QSaveFile. Текстовые файлы ограничены 256 КиБ.
Поиск ограничен 100 результатами и 10 000 записями, пропуская каталоги зависимостей и сборки.

Журнал команд показывает программу, аргументы, рабочую папку, таймаут и поступающий вывод.
Команды выполняются без интерактивного ввода. Для cmd нужен /C; /K отклоняется. Ninja вызывается напрямую с -C.
Рабочая папка ограничивает файловые инструменты и текущий каталог процесса; запуск команды не создает изоляцию ОС.

Бюджет инструментов настраивается отдельно у каждого агента. Третий одинаковый пакет действий либо исчерпание бюджета приостанавливают узел для ручного продолжения.
Результаты чтения передаются полностью, без замены ссылками на прежние сообщения.
Директивы нового агента по умолчанию запрещают добавлять комментарии в код без прямого разрешения пользователя. В .clang-format отключено автоматическое добавление комментариев к пространствам имен.

## LM Studio и мышление

Каждый агент выбирает включенное мышление, настройки сервера либо выключение.
Включенный режим использует возможности модели из /api/v1/models; для известных семейств предусмотрено резервное распознавание.
Мышление не отключается автоматически после ошибок.
Бюджет мышления задается в символах; 0 снимает дополнительное ограничение.
Таймаут, лимит токенов и бюджет инструментов — параметры конкретного узла.
Некорректный JSON, ошибка API или превышение лимита оставляют контекст доступным для ручного повтора.
Переход по непонятному либо отсутствующему значению результата автоматически не выполняется.

## Сборка Windows

Нужны CMake 3.24+, MSVC с C++23, Qt 6.4+ с Core/Gui/Widgets/Network/OpenGL, Ninja и существующая spdlog в libs.
QtNodes собирается статически. Закреплена ревизия 904f440f42dca9c89880da744b13a1d620fcc700.
При первом конфигурировании CMake получает исходники QtNodes через Git. Для автономной сборки можно разместить исходники в libs/nodeeditor
или задать ORKESTRATOR_NODEEDITOR_ROOT при конфигурировании.

```powershell
.\build.ps1 -QtRoot E:\Qt\6.4.3\msvc2019_64 -SkipTests
```

build.ps1, существующий механизм блокировки windeployqt, иконка и сборка Windows exe сохранены.
Новые изменения не собирались и проверки не запускались по указанию пользователя.
